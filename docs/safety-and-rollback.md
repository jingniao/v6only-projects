# 安全与恢复

## 部署边界

开发与隔离测试没有修改宿主机 DNS、路由、防火墙、RA、cloud-init、DynamicV6 或服务。实际生命周期命令必须明确授权。真实服务/重启验收尚未完成，当前为实验版。

选定 UID 不包含 root；前置探测检查管理服务 UID、SSH 返回路径、实际优先级、地址范围和端口。绝不使用历史公网地址、旧租约或 /root/net-snapshots/ 作为恢复基线，不整体恢复过时网卡配置。

## 事务流程

保存当前状态与文件 → 固定版本候选校验 → 独立定时恢复 → 临时应用 → 服务、选路、DNS/TLS 检查 → 等待确认 → 提交。文件快照包含内容摘要、权限、UID/GID，恢复前先验证全部必需快照。

每个事务使用唯一 service/timer 名称、绝对 UTC 截止时间、Persistent=true，并在恢复失败时保留重试机会。任务独立于后端进程。回滚 unit 本身的摘要也记录，外部修改后不盲目删除。

confirm 仅接受当前事务，不接受已超时状态；提交状态先落盘，之后才取消其专属定时器。迟到任务识别 committed，不回滚已确认变更。恢复使用快照保存的 SSH 对端，不依赖恢复进程拥有 SSH_CONNECTION；动态源地址变化不被写死为永久配置。

## 文件和内核归属

只允许本项目配置、二进制、服务文件及少量明确用途的系统路径。临时 policy-rc.d 用于阻止 APT 自启，单独保存并恢复；包管理锁仍被占用时不提前解除保护。不能证明安全的符号链接、硬链接、损坏记录或外部修改会拒绝处理。

只操作唯一 nftables 表和记录过的项目 IP 规则/路由，不清空全局表。TUN 消失后内核自动生成的 detached 标记会规范化，避免误判；新的未知选择条件仍会阻止删除。实际极端崩溃若发生在内核动作完成而其记录尚未落盘的窗口，可能需要人工核对，不能假装恢复成功。

## 卸载与清理

uninstall 先停止接管、清理项目内核和防火墙资源并验证恢复，再移除运行文件和服务，保留入口、待应用清单、历史、必要快照、依赖及日志。失败则停止清理并尝试恢复；恢复失败返回 5。

purge 必须有已确认卸载记录，且没有待处理事务和残留网络资源。先检查未知文件，再清理项目目录及专属 journal；--keep-logs 保留日志和其归属凭证，之后可再清理。--remove-entry 只删除摘要仍相符的管理入口。共享依赖始终保留，不因最初由本项目安装而删除。

清理不会删除 DynamicV6，不改现有 RA/cloud-init，不删除其他项目备份，也不清除全系统 journal/包管理日志。

## 已知边界

不能承诺抵御恶意 root 并发篡改。部署目录及父目录必须由可信管理员控制。输入、状态和候选有大小限制。普通文件恢复保存核心 POSIX 元数据；含扩展属性或 ACL 的资源拒绝自动覆盖，避免丢失未支持的元数据。不把整台机器的全部外部服务状态当作本项目快照。

systemd 实际运行、真实 SSH 断线后恢复、目标 DynamicV6 多轮对账及重启仍需专门验收。单元模拟和隔离后端测试不代替这些项目。
