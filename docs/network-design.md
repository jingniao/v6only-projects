# 网络数据路径与故障边界

## sing-box 主后端

仅支持本机默认网络命名空间内明确指定的 UID，默认不选择任何用户。运行配置固定使用官方发行包中启用的 gVisor 栈；静态校验会拒绝缺少该构建能力的二进制。UID 0 排除；检测到与 DynamicV6 管理进程/指定服务重叠的 UID 会拒绝。TUN 同时限定输入接口为 lo，避免自动接管其他命名空间的转发流量。

本机选定 UID 的 TCP/UDP 53 查询经项目 nftables OUTPUT NAT 转到 127.0.0.1/::1 的专属 DNS 端口。系统 DNS 文件和公共备用服务器配置不被改写。经 D-Bus/nss-resolve 等系统代理解析、独立 DoH 等不一定经过此路径，不能承诺自动拦截。

A/AAAA 查询统一由 FakeIP 返回虚拟地址，让目标在 TUN 中恢复成域名。命中规则的 HTTPS/SVCB 回复为空，避免地址提示绕过正常解析；未命中记录按普通 DNS 策略。FakeIP 映射存于项目私有缓存，正常重启会恢复。切换到 DNS 备用模式或改变实例地址范围后，应用旧缓存可能需要自行刷新。

路由顺序：DNS 入口劫持 → 协议嗅探 → 命中域名且仍是 IPv4 目标时拒绝 → 命中域名 ipv6_only 解析 → 再次拒绝命中的 IPv4 结果 → strict-ipv6 出站。未命中域名 prefer_ipv6，允许 IPv4 回退。

为避免主表具体路由使本机 IPv4 绕过接管，项目在 TUN 自动规则之前增加 UID 专属表查询。管理主机地址有更早的同 UID 排除规则，root 和转发流量不匹配本机 UID 查询。TUN 自动规则使用基准优先级 +16，项目保留基准至 +100 的范围。预先检查已有规则的先后顺序、表、虚拟地址和端口冲突。

后端控制进程以 root 运行并绑定自动识别的默认接口，不固定实际公网 IPv6。更高数值优先级的既有策略可以继续存在；抢先于项目规则的自定义策略会被拒绝。真实 DynamicV6 服务仍须逐机验证，不能只凭表号不同认定兼容。

## 故障保护

独立 nftables 规则允许回环、TUN 和已声明管理地址，其余选定 UID 的 IPv4 若没有经过 TUN 则拒绝。后端崩溃后保护表仍然存在，不会因为自动重启服务而先恢复 IPv4 直连。

这会在故障时影响选定用户更广泛的非管理 IPv4 流量，因此必须接受 --accept-broad-ipv4-block。disable/uninstall 是主动解除接管和限制，会明确显示影响并等待事务确认。

测试已覆盖只有 A、IPv6 路由消失、DNS SERVFAIL、后端 SIGKILL、TCP/TLS/UDP、直接 IP 的普通流量、可见 SNI 的缓存 IPv4、正常重启后的 FakeIP 映射、三轮策略更新和地址变化。其他命名空间使用相同 UID 的转发流量有独立测试。具体结果以本机最新 `.dev-state/test-results.md` 为准。

## 不能外推的保证

只能约束被接管、能够识别域名且命中规则的连接。无法关联域名的直接 IP 按普通流量处理；可见 SNI 的缓存 IPv4 会被拒绝，但不会自动改拨 IPv6。ECH、独立 DoH、任意客户端缓存、既有连接和非本项目接管流量不属于“所有情况下不可绕过”的保证。

切换/启用可能中断选定用户既有连接。没有对共享 CDN 的 IPv4 进行全局封禁。内核修改与事务日志持久化之间发生极端中断、快照损坏或外部并发修改时，恢复可能需要人工处理，不能宣称全故障场景自动恢复。

## dnsmasq 备用

仅分派/过滤 DNS，没有 TUN 出站保障。过滤服务失败时命中请求不回退普通实例；独立 DNS、缓存或直接 IP 仍可绕过。详细语义与记录类型处理见 dnsmasq.md。
